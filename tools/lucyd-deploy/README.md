# Lucyd deployment pilot

Owner: [tool charter](CATSCAN.md), [implementation/export charter](../../public/simulatte/system-diagram/deployment/CATSCAN.md), [design and evidence gates](../../docs/simulatte/lucyd-deployment.md).

This optional Lucyd feature compiles supported architectures into Kubernetes JSON and implements a real inventory API, expiry worker, receipt sink and traffic generator. It never provisions a cluster or publishes an image automatically. The Lucyd Deployment menu lazily loads the same compiler. Private plaintext exports refuse.

## Inspect and export

From the Simulatte repository:

```sh
npm ci --prefix tools/lucyd-deploy
node tools/lucyd-deploy/cli.cjs inspect \
  --input public/data/system-diagram/examples/amazon-flash-sale.json \
  --out /tmp/lucyd-inventory-plan
```

Output directories must not exist. `plan.json` names lowered source identities and supported implementation IDs. For a canonical collection, also pass `--problem ID --solution ID --stage ID`.

Copy `public/simulatte/system-diagram/deployment/configuration.template.json` outside the repository. Replace both image placeholders with reviewed, published `image@sha256:DIGEST` references. Map every `plan.nodes[].bindingKey` to one of its declared implementation IDs. Explicitly review namespace, resources, replicas, storage class, SKU, worker settings and Secret references. The template deliberately cannot compile as-is. Its resource values are example operator inputs, not inferred capacity.

```sh
node tools/lucyd-deploy/cli.cjs compile \
  --input public/data/system-diagram/examples/amazon-flash-sale.json \
  --config /absolute/path/to/inventory-deployment.json \
  --out /tmp/lucyd-inventory-release
```

`bundle.json` includes exact source/configuration/registry/object hashes, graph bindings, assumptions and explicit unexecuted qualification fields. `kubernetes.json` is a Kubernetes List containing those exact objects. No Secret values are emitted. Unsupported kernels/routes, unresolved concepts, absent bindings and image tags refuse before output is created.

Source pins are generated by `sync-registry.cjs`. After reviewing source contract changes, update them deliberately and rerun the affected tests:

```sh
node tools/lucyd-deploy/sync-registry.cjs --check
node tools/lucyd-deploy/sync-registry.cjs
```

The browser verifies public source pins. CLI additionally checks the local implementation source pins. Registry/image provenance and actual published image availability remain operator gates.

## Local implementation and checks

Requires Node 22 and Docker running locally. PostgreSQL integration starts its own PostgreSQL 17 Alpine container on a random loopback port, uses random ephemeral credentials, and removes the container and its volume afterward.

```sh
npm test --prefix tools/lucyd-deploy
npm run test:postgres --prefix tools/lucyd-deploy
docker build --tag lucyd-inventory:local tools/lucyd-deploy
npm run test:container --prefix tools/lucyd-deploy
```

`app/main.cjs` roles are `api`, `worker`, `events`, or `traffic FILE`. API/events/worker require `DATABASE_URL`, `SKU`, `INITIAL_STOCK`, `RESERVATION_TTL_MS`, `MAX_RESERVATIONS` and `API_TOKEN`; worker also requires `LEASE_MS`, `POLL_MS`, `EXPIRY_BATCH_SIZE`, and optionally `EVENT_SINK_URL`. Traffic requires `BASE_URL` and `API_TOKEN`. Keep runtime credentials outside Git and shell history. Docker build has a digest-pinned Node base and copies only application sources and the lockfile.

| HTTP route | Contract |
|---|---|
| `GET /livez` | Process liveness; no authentication |
| `GET /healthz` | Database readiness; no authentication |
| `GET /v1/inventory` | Bearer authentication; available/held/sold counts |
| `POST /v1/reservations` | Bearer token, Idempotency-Key, `{customerId,quantity:1}` |
| `POST /v1/payments` | Bearer token, Idempotency-Key, `{reservationId}`; no financial charge |
| `POST /events` | Event role only, bearer token, `{id,kind,payload}` |

Stock conservation and idempotency are persisted transactionally. Expired worker leases recover; outbox delivery retries and receiver identities deduplicate. The local checks use actual SQL and HTTP, not mocked persistence. They cover concurrent buyers/payments, response loss, conflicting key reuse, duplicate identities, leased expiry, receipt redelivery, server restart and PostgreSQL restart. A separate restricted-container test kills the actual API and both expiry workers, verifies lease recovery, and restarts PostgreSQL. These checks do not establish cloud pod/network/storage behavior.

Optional browser audit (requires a Playwright installation and local Chrome):

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
  node tools/lucyd-deploy/tests/browser.mjs
```

The audit starts and closes its own local server. It verifies desktop/mobile export, private plaintext refusal, cleanup and viewport bounds; its default screenshots/report directory is `/tmp/lucyd-deployment-browser`.

## Operator-owned cloud gates

No cloud resource was created by these commands. Before applying the bundle, publish and verify the implementation image, verify the PostgreSQL image contract (17 Alpine, UID/GID 70), select the intended cluster/context, create matching external Secret values, review persistent storage, and run server-side dry-run against that exact context. The API is internal-only; no ingress, TLS, public IP, cloud IAM or managed database is generated.

After deployment is authorized, retain its image/source digests and release events, then run traffic and failure checks. PostgreSQL has one replica; a PVC is not a backup or high-availability design. Never claim GKE deployment from compilation or Docker tests. AWS, managed databases, automated cloud lifecycle, encrypted deployment export and observation-comparison UI remain unsupported.
