## Scope and counts

The canonical registry now has 31 public problems, 32 approaches and 256 stages.
Every public approach has one requirements/design stage and seven executable
stages. Fifteen encrypted private approaches add 120 stages. See the
[study contract](../../public/simulatte/system-diagram/study-contract.js) for the
eight-stage acceptance policy and [study model](lucyd-study-model.md) for privacy
and versioned save migration. Counts describe the authored registry; deployed
availability requires a release receipt.

| Previously missing problem | Authored path | Executable evolution |
| --- | --- | --- |
| `database-service` | Isolated tenant databases and recovery | Tenant isolation, follower receipts, tenant-specific recovery |
| `project-review` | Worked project review: asynchronous reports | Blocking deadlines, bounded admission, ambiguous commit recovery |

| `chat` | Connections, delivery and ordered history | Ambiguous acknowledgement, retries, sessions, presence, fan-out, disconnected-device catchup |
| `replication` | Explicit cross-region replication and catch-up | Local acknowledgement, remote acknowledgement, retry repair |
| `saved-search` | Saved matches and retryable daily digests | Retained matches, recipient/day digests, acknowledgement recovery |
| `load-balancer` | Round robin routing, retries and probes | Error exposure, retry/ejection, request-driven circuit probes |
| `subscriptions` | Versioned subscriptions and payment recovery | Duplicate charges, idempotent lifecycle, ledger reconciliation |

Each new path retains its three original executable scenarios within eight substantive stages and a fixed
configured source/seed contract. Completion counts, effects and retries are
separate. Closed-loop arrival timing is not claimed equal across architectures.
The source problem text and provenance classifications remain unchanged. Answers
to sourced exercises are authored practice, not company-verified architectures.
The project-review answer is a worked example, not the reader's employment history.

## Existing path corrections

- Chat application now executes a stream crash and bounded recovery; acknowledged
  chunks and durable message identity survive without duplicate effects.
- Social feed now executes fanout retry exhaustion and dead-letter quarantine;
  queue acceptance is explicitly distinct from timeline delivery.
- RAG prose describes synthetic count/publication/service-time behavior rather
  than claiming semantic retrieval or cross-encoder quality measurements.
- Video prose removes unsupported regional locality and offload percentages.

Evolution stages and detail levels are separate axes, documented in
[system-diagram.md](system-diagram.md). Walkthrough steps explicitly distinguish conceptual requirements from executable
architecture experiments. Synthetic service times, finite
traces and in-memory state do not establish production capacity, real durability,
SMTP/WebSocket delivery, provisioning or cloud deployment capabilities. The
implementation/deployment compiler support set was not expanded.

## Follow-up shared-kernel and lifecycle review

The repeat/interruption review added regressions and corrected three API cases:
repeated mutation preserves unique sorted keys; an old charge acknowledgement
cannot undo a same-version cancellation; crash clears orphan pending calls while
retaining committed lifecycle identity. Event-ledger lookup uses own keys so
prototype member names cannot masquerade as committed events. The focused run
passes 76/76 tests after those fixes. Each new stage still passes coordinator
verification and checkpoint continuation.
